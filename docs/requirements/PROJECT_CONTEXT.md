# Project Context — User's Real Workflow and Agreed Decisions

This document is a condensed record of user-provided context that a new Codex session would not know. `MASTER_IMPLEMENTATION_PLAN.md` contains the technical specification; defer to it if anything here is ambiguous.

## Current job-application workflow

1. Find a job posting.
2. Copy its job description into a dedicated ChatGPT conversation (the user describes it as the `resume/oas/jobs` conversation, using an "Update repo..." workflow) that tailors the resume.
3. Download the job-specific PDF generated by ChatGPT. **A different PDF is created for each posting.**
4. Click Apply on the employer's Workday job page; select Workday's **Autofill with Resume** path.
5. If the employer requires an account, create a password-based account or sign in; if Google sign-in/sign-up is offered, the user prefers using that option.
6. Upload the tailored PDF through Workday's resume uploader and proceed.
7. Check all Workday parsed fields for errors.
8. Workday often incorrectly fills **My Experience**; manually repair education and employment details.
9. At Skills, ask ChatGPT which skills to add; manually search the Workday skills dropdown. Some skills listed in the tailored resume cannot be found in Workday's dropdown.
10. Fill LinkedIn, GitHub, and portfolio fields if available.
11. Answer other application questions manually, review each section, click Apply/Submit manually, see confirmation.

## Product decisions from the conversation

- Build a polished, open-source **Chrome extension**, not just a Tampermonkey macro or external Selenium client. TypeScript + React + Manifest V3; Playwright for browser tests.
- Keep the current job discovery and ChatGPT resume-tailoring workflow; do not require a new job search system or moving the existing resume repository.
- Support **both tailored PDF-only imports and an optional matching structured JSON companion**. JSON is more reliable but must not be required. A tailored PDF may change per job, and the skills chosen for the application should change with it.
- Maintain a canonical, user-verified **master profile** separate from per-employer/per-job **application profiles**. Correct inaccurate Workday parsing using the verified data, including repeated experience/education records.
- Recommend skills by comparing the tailored resume and job description with the user's **verified actual skills**. Automate searching/selecting dropdown matches, alias spellings, checking actual options, and reporting unavailable skills. Do not falsely add or claim unrelated skills.
- Automate ordinary fields, hyperlinks, radios/checklists/dropdowns and reusable non-sensitive confirmed answers. Propose custom-question drafts; let the user review them. AI-generated open answers are an optional separate enhancement, not mandatory for v1.
- Detect and scan **each** application step, verify filled values and visible errors, never silently overwrite manual changes, and never automatically click Next or Submit.
- Recognize each employer's Workday candidate portal/account separately, assist with registration email and account registry, but let Google SSO, password manager, OTP, CAPTCHA, consent and credential entry remain user-controlled. Do not store passwords.
- Preserve Workday's native resume upload/parser workflow and use the extension primarily to correct and augment it; don't promise universal programmatic upload.
- Local first, no mandatory external services, no auto-submit, no fabricated job qualifications, no sensitive-question autopopulation.

## Most important functionality, in priority order

1. Accurate, reviewable Workday My Experience corrections and other verified profile fields.
2. Tailored-resume + job-description skill selection with realistic missing-skill behavior.
3. Per-step verification and user-controlled filling.
4. Resume PDF and companion JSON imports.
5. Saved answer memory, custom-question assistance.
6. Per-employer account setup support and application history.
7. Optional AI integration / other ATS platforms only after the deterministic MVP is solid.

## Expectations of Codex

Build working code rather than only producing mockups. Organize the code into testable independent modules. Simulate Workday's tricky controls and tenant-specific configurations with synthetic fixtures. Keep an explicit implementation progress file and be transparent about anything untested on real Workday sites. The user will review changes, load the Chrome extension and provide real-portal QA observations. Never require access to this private ChatGPT chat or repository for the extension to work.
